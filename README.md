_Перше виконане_
**Завдання 2: Аналіз структури файлу package.json**
**1. Опишіть у звіті призначення полів файлу package.json: name, author, description, version, license, repository, scripts, dependencies, devDependencies.**
name - устанавливает имя проекта,
author - автор проэкта,
descritpion - короткое описание проэкта,
version - версия проэкта,
license - тип лицензии,
repository - Информация о репозитории, указывает тип и адрес,
scripts - набор команд, которые можно запускать через npm,
dependencies - перечень зависимостей, которые нужны для работы программы в продакшене,
devDependencies - перечень зависимостей, необходимых только для разработки.
**2. Проаналізуйте залежності, вказані у dependencies та devDependencies, поясніть логіку такої класифікації.**
В dependencies указаны зависимости для прода, а в devDependencies для разработки(dev).
**Завдання 3: Семантичне версіонування (SemVer)**
**Дослідіть версії пакетів бойлерплейту. Поясніть, які оновлення (мажорні, мінорні, патчі) допускаються відповідно до версій, зазначених у файлі package.json.**
У бойлерплейті в основних залежностях (dependencies) переважно використовується позначення ^, тобто дозволені мінорні та патч-оновлення, але не мажорні.З цього випливає, що оновлення бібліотек можливі лише в межах поточної мажорної версії

У залежностях для розробки (devDependencies) також використовуються ^, що допускає мінорні оновлення
Отже, зміни, які можливі в цьому бойлерплейті:
    >> Дозволені мінорні та патч-оновлення для всіх залежностей.
    >> Мажорні оновлення заборонені без ручного втручання.

**Завдання 4: Дослідження додаткових конфігураційних файлів**
README.md - Все, что нужно для запуска веб-приложения 
.gitignore - всё, что не нужно пересылать на удаленный репозиторий
LICENSE - описана лицензионное соглашение
**Завдання 5: Аналіз роботи гіт-хуків Husky**
Дослідіть артефакти, які створюються після встановлення та налаштування бібліотеки Husky.
Опишіть, для чого потрібні ці артефакти, як вони налаштовуються та яку роль відіграють у процесі розробки.
-> 
Після встановлення та ініціалізації Husky у проєкті створюються такі файли та директорії:
- node_modules/husky
- .husky/ - забезпечуючи налаштування Husky.
- .husky/_/husky.sh
- .husky/pre-commit - перед кожним комітом виконується npm run lint, що запобігає коміту неякісного коду
- .husky/pre-push
- package.json (оновлений) и тд
Husky дозволяє автоматизувати контроль якості коду перед комітом та пушем, що допомагає уникати помилок та підтримувати проєкт у чистому стані.
